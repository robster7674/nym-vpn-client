NymVPN on FreeBSD

The headless NymVPN daemon and CLI now build and run on FreeBSD amd64. The daemon starts, answers nym-vpnc over its socket and reads the live gateway list. A full tunnel connection has not been tested yet because it needs a Nym account.

Starting point

The only existing upstream trace of FreeBSD was nymtech/nym-vpn-client#2307, a packaging request closed in March 2025. A source read before any compiling suggested the real problem was a port, not a package. The first compile on FreeBSD 15.1 confirmed it, and showed the gap was small.

What testing on a real FreeBSD host turned up

The daemon refused to start because of a newline

The kernel version string FreeBSD reports ends with a newline. It went into the HTTP User-Agent header and the API client failed with failed to parse header value. Fixed by trimming the values, with a regression test.

pf rejected the NDP rules

pf wants icmp6-type after the addresses, not before. Only a run of the real parser found it. Fixed, and an ignored test now feeds every generated policy to pfctl -n.

pfctl needs root, even for a dry run

On FreeBSD 15 pfctl talks to the kernel over netlink, so -n fails for a normal user. Tests that touch pf are marked ignored and are run as root.

Go cannot build the WireGuard archive on arm64

-buildmode=c-archive is not listed for freebsd/arm64 in Go's platform table, although the runtime has the library entry point. Worked around: the build script now builds the Go tools from a patched copy of GOROOT (a one-line diff, in the same style as the existing Android and macOS runtime patches) and libwg.a builds on arm64. Whether the resulting daemon runs is still being checked, in #2. A longer-term option is FreeBSD's in-kernel WireGuard (if_wg), in #6.

A custom pf ruleset was suspended while connected

The first firewall version always replaced the main pf ruleset. Improved: if /etc/pf.conf already has anchor "nym" as its first filter rule, the host's rules are kept and only the anchor changes. Without it the old behaviour remains and the daemon logs a warning. Tracked in #3.

The Go toolchain must be 1.27

go.mod requires Go 1.27 and the default go package is 1.26. The go127 package is used instead.

For the UTM test machine

On an Apple Silicon Mac, download the VM, aarch64 image of FreeBSD 15.1-RELEASE (not the BASIC-CI one) and import it into UTM as an existing disk with UEFI boot. It matches the GCP arm64 VM. Build steps and the install layout are in nym-vpn-core/crates/nym-vpnd/freebsd/README.md.

pkg install git protobuf go127 cmake pkgconf gmake bash rust
export PATH=/usr/local/go127/bin:$PATH
./wireguard/build-wireguard-go.sh      # amd64 only for now
cd nym-vpn-core && cargo build -p nym-vpnd -p nym-vpnc
